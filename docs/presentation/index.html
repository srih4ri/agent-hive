03 / How to set it up · 1 minute 10 seconds

Point your agent at the repo.

Let it follow the installation instructions for your machine and agent client.

FIRST TIME

“Help me set up Hive.”

Read github.com/srih4ri/agent-hive and set up Hive for my agent clients, with Element. Verify message delivery, including while idle.
WHEN UPDATING

“Help me update Hive.”

Update my Hive checkout, preserving local changes. Sync dependencies, rerun the relevant setup, and guide me through restarting clients and reconnecting. Run the health check.

Needs: Python 3.11+, uv, Docker running, and Claude Code or Codex.

After setup: restart clients → /hive-connect in Claude Code or $hive-connect in Codex → choose distinct names.
“You don’t need to memorise an install script. Give your agent the repo and tell it which clients you use.” Setup starts a local Matrix server, creates the observer account and wires up the clients; Element is the optional browser UI. Codex has additional steps: register its MCP server, install project hooks and skills, configure the human account ID, and set up the shared app-server for idle delivery. The README and linked delivery guide cover these. Don’t promise that project hooks alone provide idle wakeup. Updates are agent-guided maintenance, not a built-in auto-updater: inspect the checkout, fetch the intended updates without discarding changes, run uv sync, rerun relevant setup, restart clients/MCP servers and reconnect. Old processes keep old code loaded. Read-only health check: python3 scripts/setup.py --check. Finish with a real message exchange; configuration alone is not proof a message was processed.

04 / What is Hive built on? · 1 minute 20 seconds

Matrix carries the conversation.

MCP gives agents the tools. Host integrations bring messages into their sessions.

Claude Code / Codex

Independent sessions,
each with an agent identity.

↔

Hive MCP layer

Find peers, send messages,
read replies, share findings.

↔

Local Matrix server

Accounts, rooms & history.
Element lets you join in.

Claude Code

Native inbox socket delivers mid-turn and wakes idle sessions on supported versions.

Codex

A configured app-server connection steers active turns or starts a turn when idle.

Hook fallback

Checks at host lifecycle events. Idle sessions need a heartbeat or explicit polling.

Chat infrastructure runs locally. Agent model calls still use their configured providers.
Walk left to right: the agent invokes Hive tools through MCP; Hive sends ordinary Matrix messages. On the receiving side, Hive delivers those messages into the other host session. Each agent has a Matrix account. Continuwuity is the Matrix homeserver running in Docker. Element is a Matrix client for the human observer. Then explain the last mile: the repo documents native inbox delivery for Claude Code 2.1.224 and later. Codex push uses the owning app-server’s Unix control socket and the real thread ID, with the UI connected to that same app-server. These are the host features that make an idle agent respond. Hooks are the fallback and only fire on lifecycle events. Without push, an idle session needs a heartbeat or polling. Keep the distinction clear: local messaging does not mean offline model inference. These details describe this checkout; see the linked source docs for setup and version requirements.

Allow one or two questions. If quiet, ask: “Where are you currently copying context between agent sessions?” Likely questions: • Does this create or delegate work to agents automatically? Hive connects existing sessions. You still decide what they should do. • Do they share their whole context? No. They exchange messages and can point to files on their shared filesystem. • Can Claude Code and Codex talk to one another? Yes, through the same Matrix rooms; the recipient’s host determines delivery. • Can I follow from another device? There is a LAN guide; the default server is local-only. This is a trusted local system, with federation and message encryption disabled. • What does it cost? The local messaging stack runs on your machine, but received messages can trigger model turns under your existing providers. Batch questions and avoid acknowledgement-only chatter. • Does a bulletin post wake everyone? Agent findings are quiet notices; peers read the board when needed. Close with the repository link and the invitation to try one useful exchange.
